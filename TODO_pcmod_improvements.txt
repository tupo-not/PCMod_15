- DONE: Start menu and All Programs now follow cfg.GuiScale like program
  windows; both stay a bottom-left block (bottom edge on the taskbar) with All

- DONE: GUI Scale presets now include 25% and 50% (floor is 0.25); the font

- DONE: Fixed the Start button / taskbar needing pixel-hunting: the HackyClicky

- DONE: Window drag/resize now starts on the actual mouse-press edge (GMod's

- DONE: Multi-window support: personal-OS programs open as cascaded desktop

- DONE: Windows can be resized by dragging the bottom-right grip; the layout
  rebuilds live and "win_resize" stores the size/server-side
- DONE: LAN addressing renumbered: the router is 192.168.x.1 (its IPv6 is the
  /64's ::1 gateway) and PCs are assigned .2, .3, ...; dropped the legacy
  one-octet-per-group IPv6 form and the old .0 gateway mapping
- DONE: LAN DHCP: routers hand out IPv4 leases from a configurable pool
  (cfg.DHCPStart/cfg.DHCPEnd, default .2-.254) instead of four fixed cable
  slots; when the pool is full the client is still admitted as IPv6-only (the
  Control Panel shows "IPv6 only"), mirroring a real DHCP server. cfg.LanNetmask
  is 24 for now; /16 depends on the IPv6-only addressing pass
- DONE: IPv6 renumbered to a real hierarchical scheme: one global fd00::/16,
  one /32 per backbone router (fd00:<bb>::/32) and one /64 per LAN router
  (fd00:<bb>:0:<net>::/64); a standalone LAN uses fd00:0:0:<net>::/64. LANs no
  longer know about the WAN/backbones, the old flat fd00:c0:a8 / fd00:a:0
  formats were dropped, and routers match destinations against their /64 then
  /32 prefixes
- DONE: Routers expose a minimal web server: any in-game computer that sends
  { "http", path } to port 80 of the router gets a plain-text config page

- DONE: All programs now reset their window payload (DeviceData) on every open

- DONE: Router web page has a Configuration panel with editable text inputs

- DONE: Router firewall is now a rules-based allow-list (default deny):

  port-forwarding (DNAT/SNAT) rules onto the same page. Firewall on = block
  everything except web/ping, established NAT replies and matching allow rules
- DONE: Router port forwarding (DNAT/SNAT): add/delete lan rules via the web
  page (wan port -> local ip:port), inbound traffic to a forwarded port is
  re-targeted at the internal host and replies are source-NAT'ed back to the
  address the peer dialled (not the router's private LAN IP)
- DONE: Router web UI is split into pages (home/status + Wi-Fi/LAN/firewall
  sub-pages) with a shared navigation bar of relative links; the browser tracks

  plus its mock - LAN addressing is now wholly the router's per-router DHCP
- DONE: Backbones run a distance-vector routing protocol: each learns every
  reachable /32 (next hop + hop count) and reconverges whenever a backbone link
  is added/removed, so IPv6 routes across any number of backbones. LAN routers
  auto-renumber their LAN (and every client lease) when their upstream /32-/64
  changes on connect/disconnect
- DONE: Private, isolated LANs: each router owns 192.168.0.0/24 or /16
  (cfg.LanNetmask), overlapping with every other router - a LAN knows nothing
  about upstream. 192.168.x stays LAN-local; the 10.x backbone space routes
  across backbones and is NAT'ed at the edge
- DONE: Full IPv4 NAT: 10.x backbone /32s route across the backbone graph, a LAN
  router masquerades (source-NAT) its private hosts behind its own /32, and a
  router NATs inbound forwarded ports (DNAT) to an internal host - replies are
  translated back at both edges, so a client behind one router reaches a service
  behind another router's /32 (e.g. 10.0.2.2:72 -> 192.168.0.2:72)
- DONE: PAT (port-address translation): packets carry a SourcePort, the router
  hands each connection a stable ephemeral source port (masquerade + forwarded
  port), and replies translate back by that port, so many hosts share one public
  /32 or one forwarded port at once. OS replies (netDataRecieved handle) use the
  source port, and chathost tracks clients by (ip, port) so multiple NATed
  clients can chat through one server
- DONE: Garry's Mod duplicator (save/copy/paste) compatibility: PreEntityCopy/
  PostEntityPaste save a full snapshot (hard-drive VFS, IP, power state, login
  password, and per-router config/wireless) via duplicator.StoreEntityModifier;
  paste restores it, re-syncs the address strings, re-applies wireless and
  boots an on computer back up. PCTool.SpawnEntity (the registered duplicator
  function) also restores the saved hard drive. AdvDupe2 works through the same

- DONE: Explicit IPv6 routing table: backbones map child /64s and peer /32s to

- DONE: LAN DHCP moved onto the router (per-router lease pool, /16 spans both

- DONE: IPv4 backbone hierarchy now mirrors IPv6: 10.0.0.0/8 -> one block per
